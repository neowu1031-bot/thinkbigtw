What Does a Pre-Delivery Security Review of an AI Agent Actually Check?

Think BIG Q&A Library  ·  2026-10-19   ·  中文

The short answer

It checks the exact version being delivered, not some version from during development: code and configuration, outbound connections, permissions, keys, and third-party packages and models, each against a checklist with a record kept. If it does not pass, it is not delivered. No one can promise perfect security; the point of a review is to rule out known risks one by one and leave a record of what was checked and what was found.

1. Eight checks

Common pre-delivery checks for AI Agents, mapped to the OWASP Top 10 for LLM Applications 2025:

# Check What is examined Related risk
1 Version match The reviewed files are the same files being delivered (for example, by comparing hashes), so "reviewed A, installed B" cannot happen Supply chain (LLM03)
2 Outbound connections Which external services the system is expected to reach and what data it sends; nothing outside the list Sensitive information disclosure (LLM02)
3 Permissions Each AI Agent has only the tools and data its job needs, verified with tests that forbidden actions fail Excessive agency (LLM06)
4 Keys API keys are not in code, not in the repository, not in system prompts or chat logs; only in permission-protected configuration System prompt leakage (LLM07)
5 Third-party packages and models Trusted sources, clear licenses, pinned versions with no auto-update; model files checked by hash Supply chain (LLM03)
6 Handling outside content Web pages, emails, and documents the AI reads are not treated as instructions; output formats checked in code Prompt injection (LLM01), improper output handling (LLM05)
7 Document and data permissions The knowledge base retrieves by user permission, and even citations do not expose restricted content Vector and embedding weaknesses (LLM08)
8 Records and recovery What changed, why, and how to roll back to the previous version are all recorded Governance (NIST AI RMF)

Under supply chain risk, OWASP recommends using only models from verifiable sources, checking integrity with signing and file hashes, keeping an up-to-date software bill of materials (SBOM), and inventorying the licenses involved. Under system prompt leakage, it states that credentials and connection strings should not be in the system prompt.

2. How results are decided

Use three outcomes, agreed in advance:

  • Pass: every check is met; delivery can proceed.
  • Conditional pass: issues exist but the risk is manageable; the required fixes and deadlines are listed and confirmed once done.
  • Fail: issues that could leak data, allow unauthorized actions, or prevent recovery; no delivery until fixed and re-reviewed.

The review is best done by someone not involved in development, with a record of which version was reviewed, how each item was checked, and what was found. The U.S. NIST AI Risk Management Framework (AI RMF 1.0) organizes AI risk management into four functions (Govern, Map, Measure, Manage), and NIST published its generative AI profile (AI 600-1) on July 26, 2024. Review records are the evidence for Measure and Manage.

3. After delivery

Passing at delivery does not mean safe forever: models update, packages get vulnerabilities, permissions get adjusted. Every later change should re-run the affected checks from the same list. Companies can write into the contract which changes trigger a new review and who keeps the records.

FAQ

Q1: How is an AI Agent security review different from a regular software security check?
Besides versions, keys, packages, and permissions, an AI Agent review checks whether outside content it reads can be treated as instructions (prompt injection), whether its permissions exceed the job (excessive agency), and whether the knowledge base can hand restricted content to users.
Q2: Why confirm that the reviewed version matches the delivered version?
If the review covered a development version and a few lines changed before delivery, the review means little. Comparing file hashes confirms the reviewed files are the ones delivered.
Q3: Does passing a security review mean the AI Agent has no vulnerabilities?
No. No one can promise perfect security; a review rules out known risks one by one and keeps a record. Every change after delivery should re-check the affected items.
Q4: Which standards can an AI Agent security review follow?
Common references are the OWASP Top 10 for LLM Applications 2025, the OWASP Top 10 for Agentic Applications for 2026, and the NIST AI Risk Management Framework (AI RMF 1.0) with its generative AI profile, AI 600-1.
