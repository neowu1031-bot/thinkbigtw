TB FRAME METHODOLOGY

Four phases.
Defined deliverables.
Verifiable results.

TB FRAME is Think BIG's structured approach to enterprise AI Agent deployment. Every phase produces a written record of deliverables, acceptance criteria and the conditions for hand-over — so you know exactly what was built and when it is ready to operate.

Phase 1: AssessPhase 2: BuildPhase 3: ValidatePhase 4: Operate
PHASE 1

Assess

Define the scope and confirm that deployment is viable before writing a line of code.

Deliverables
Workflow map of target processes; data inventory (sources, formats, access conditions); risk and dependency register; a proposed scope document signed off by both sides.
Acceptance criteria
Client confirms the scope document accurately reflects the target workflows; data sources are accessible for integration scoping; no blocking dependency is unresolved.
Hand-over condition
Written scope approval by the client's designated contact before any build work begins.
PHASE 2

Build

Develop the AI Agents and integration layer against the agreed scope.

Deliverables
Configured AI Agents; knowledge base or retrieval setup; integration connectors; operator guide; test scenario list prepared for Validate phase.
Acceptance criteria
Agents respond to test scenarios within the agreed knowledge boundary; integration connectors return expected data; operator guide reviewed by client.
Hand-over condition
Client confirms readiness for structured acceptance testing before Validate begins.
PHASE 3

Validate

Run structured acceptance tests against agreed scenarios, document results and resolve gaps before go-live.

Deliverables
Acceptance test results (pass/fail per scenario); gap resolution log; signed acceptance record; go-live checklist.
Acceptance criteria
All agreed test scenarios pass or gaps are resolved and re-tested; client's designated contact signs the acceptance record.
Hand-over condition
Signed acceptance record and completed go-live checklist before the system is opened to end users.
PHASE 4

Operate

Support stable operations, monitor for anomalies and manage knowledge updates during the service period.

Deliverables
Scheduled maintenance reports; anomaly and resolution log; knowledge base update records; scope-change requests (for items outside the original scope).
Acceptance criteria
Maintenance reports are delivered within the agreed schedule; anomalies are responded to within the agreed SLA; scope-change items are logged and priced before work begins.
Hand-over condition
Handover only occurs after a formal transition review when the service period ends or a new scope agreement is in place.
