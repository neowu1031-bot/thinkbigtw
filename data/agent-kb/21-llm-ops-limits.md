# 21｜本地大模型專業問答：更新維護、常見失敗與限制
版本：2026-10-31
來源：內部本地模型建置必查清單（GPU 是否真的在用、上下文設定、中文帳號路徑、版本釘住）；Think BIG NEWS〈本地跑大模型，GPU 真的有在動嗎？〉〈AI 的記憶設太大反而把整台電腦拖垮〉；問答圖書館〈本地大模型的缺點〉（Stanford AI Index 2025、NIST SP 800-40 Rev.4、OWASP Top 10 for LLM 2025）〈本地模型夠不夠聰明？〉（Ollama 官方 FAQ 預設上下文 4096、ollama ps）。

更新：固定版本、不自動更新（有些本機工具桌面版預設會自動下載更新，要改成手動）。有新版模型或軟體，先在測試環境用同一批測試題重測，沒有退步才換；保留舊版可退回。換模型不用整套重做，但流程與輸出品質要重新驗證。首年維護含必要安全修補與監控。

常見失敗原因：
①模型其實在用 CPU 算，畫面正常但每題等好幾分鐘。檢查：ollama ps 的 PROCESSOR 欄顯示 100% GPU 才是全部在顯示卡；出現 CPU 比例代表有一部分在 CPU；API 回報的 size_vram 是 0 就是全在 CPU。驅動太舊、偵測失敗、使用者帳號或安裝路徑有中文字元，都可能讓它默默改用 CPU。
②上下文設太短：預設值依版本與設定而不同，太短時文件段落放不進去，AI 看起來就「變笨」。③上下文設太大：記憶體被吃光，整台電腦不穩。要依機器規格抓合理值。
④模型太大放不進顯示記憶體，比小一號、能整個放進顯示卡的模型還慢。⑤同時提問的人多，請求排隊。
⑥文件過期或互相矛盾、權限沒分、切段不當、只測簡單的題目。⑦沒人負責維護更新，或沒從員工每天真的會做的那件事開始，導入後沒人用。
地端版交付前一定確認 GPU 真的在跑、用公司真實問題測速度，並用會呼叫工具的任務實測。

回答很慢怎麼辦：依序檢查 GPU 是否真的在用 → 模型是否超過顯示記憶體 → 上下文長度 → 同時提問人數。超出標準負載時另案評估，以實測為準。

本地大模型的限制：要有一台合規格的專用設備（已有設備先預檢，不足才增購）；能力通常比不上最新的雲端大模型；要有人維護、更新、監控；用量少或起伏大時設備常閒著；電力、散熱、折舊、備份與災難復原回到公司身上；放在地端也不會自動解決提示注入與權限問題。
什麼情況雲端比較合適：資料可以出門、用量小還在試、工作需要最新雲端能力且地端實測不夠、公司沒有人或廠商能維護。常見做法是依資料分級混用：機密與個資走地端，一般工作走雲端輔助版。
