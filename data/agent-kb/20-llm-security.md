# 20｜本地大模型專業問答：資安怎麼做
版本：2026-10-31
來源：官網 /trust/、/guides/local-ai-data/、/faq/（資安定調）；內部《企業建置手冊》安全鐵則與標準組合（防火牆預設拒絕、內網固定 IP、對外不開埠、固定版本）。
來源：問答圖書館〈本地模型斷網可以用嗎？〉（Ollama 官方 FAQ：OLLAMA_NO_CLOUD、自動更新；OWASP LLM03:2025 供應鏈）〈AI 系統要留哪些紀錄？〉（OWASP Logging Cheat Sheet、個資法施行細則第 12 條、NIST AI RMF）〈提示注入是什麼？〉（OWASP LLM01:2025）〈AI Agent 的權限要怎麼設？〉（OWASP LLM06:2025）〈本地大模型有什麼優勢？〉（國科會生成式 AI 參考指引第四點）。

資料會不會離開公司：地端版的模型、文件與回答都在公司設備內處理，不經外部模型廠商。但地端不等於所有連線都在本機，要一起確認：工具雲端功能、LINE 等外部通路、遠端維護連線、日誌與備份放哪。部署附件逐項列出資料路徑，整條驗證過才說資料不出公司。
用 LINE 當介面：LINE 的訊息會經過 LINE 平台與轉接服務（例如 Cloudflare），會列在資料路徑裡；要資料不出公司，介面改用內網登入式網頁。
斷網／內網：模型下載到本機後，回答不需要網路。可只在內網服務、防火牆預設拒絕、對外不開入站埠，並在封鎖外連下實測。更新改在連網環境下載、核對來源與雜湊值、測試題跑過再搬進來。遠端維護需要連線，完全離線時維護方式另外約定。
稽核紀錄：標準建置的管理員可在後台看問答紀錄（誰、何時、問什麼、AI 怎麼回）；更細的稽核（匯出、讀了哪些文件）評估時依需求規劃。紀錄含個資，要訂保存期限、限制誰能讀、遮蔽密碼金鑰與敏感個資。
提示注入：把指令藏在 AI 會讀的文件或網頁裡騙它；OWASP 列為大型語言模型應用十大風險第一項，沒有萬無一失的防法。做法是讓 AI 被騙也做不了危險的事：外部內容當資料不當指令、最小權限、對外發送／花錢／改正式資料由人核准（草稿只擬不送），驗收加入攻擊測試題。
我們的資安做法：套件裝之前先掃描、審查來源授權、固定版本不自動更新；金鑰只放受保護的設定檔、不在對話裡傳；每套系統交付前先過資安審查（比對實際交付版本、檢查外部連線與權限、確認金鑰不外露），沒通過不交付；異動前備份、可回滾。這是我們的治理做法，不是第三方資安認證，也沒有宣稱持有 ISO 27001 等認證；部署附件與權限設計可給貴公司 IT 或稽核檢視。
資安沒有人能打包票，也不說「100% 不外洩」；我們做的是一道一道的審查，並把資料流向寫清楚。
個資：利用不超出蒐集目的；能去識別就先去識別，或只放地端版。個案請洽律師。
