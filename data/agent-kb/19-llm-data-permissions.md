# 19｜本地大模型專業問答：文件準備、權限與出處
版本：2026-10-31
來源：官網 /enterprise/rag/（RAG 定義、資料準備、驗收、常見失敗原因）；內部《企業建置手冊》知識庫建置與 App 規格（2026-09-27 查核）。
來源：問答圖書館〈公司文件給 AI 查，怎麼讓每個部門只看得到自己的資料？〉（OWASP LLM08:2025、LLM06:2025）〈用 AI 查公司文件，雲端版跟地端版的資料各會送到哪裡？〉（OpenAI API〈Your data〉、Anthropic Privacy Center，2026-10-19 查證）。

RAG：AI 回答前先從公司文件找出相關段落，再依段落回答並附出處；更新文件不用重新訓練模型。微調是用範例調整模型參數，不會自動附出處、也不能代替權限檢查；企業標準範圍不含模型訓練，多數知識問答用 RAG 就夠。
文件準備：標準範圍收可選取文字的 PDF、Word（DOCX）、純文字、單純試算表；掃描檔或圖片要先 OCR 辨識，不在標準範圍。每份文件要有負責人與有效版本，移除過期、重複的；範圍凍結前先拿樣本試匯入。文件幾千份或主要是掃描檔，評估時另規劃。
權限：原則是在「找資料」那一步就擋，不能只靠提示詞叫 AI 不要說；做法是文件標上可讀範圍，提問時只從這個人有權看的文件找段落。標準方案是 1 個知識庫＋2 種使用身分（管理員、一般同事），不等於部門文件隔離，所以人事、薪資這類高度敏感資料不建議放進標準方案的知識庫。需要部門分權或多個知識庫屬另案評估，做完要用「這個人不該看到」的測試題驗收，確認回答和出處都沒露出來，再放敏感文件。
出處與答錯：回答會附出處可回查；找不到依據就回「查不到，請洽指定窗口」，不讓 AI 用常識亂補。AI 仍可能答錯，所以用測試題驗收、重要決定由人確認，不承諾準確率。
文件更新：有唯讀串接（例如雲端硬碟資料夾）時定期同步，新增、修改、刪除都會更新索引；沒有串接就由管理員上傳。舊文件撤回時索引要一起刪。
資料會不會被拿去訓練：地端版的模型在公司設備上執行，回答問題不會改變模型本身，也不送到模型廠商；我們不拿客戶資料訓練模型。雲端輔助版依模型廠商當時的條款，例如 OpenAI 官方說明預設不拿 API 資料訓練模型；資料保存多久依使用的功能而不同，簽約時以當時條款逐項核對。
上網查資料：可以加網路搜尋，但搜尋字詞與讀取網頁都會連外，網頁內容也可能藏提示注入；地端知識庫問答預設以公司文件為主、不開上網，要加另行評估。
