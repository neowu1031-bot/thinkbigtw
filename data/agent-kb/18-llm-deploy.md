# 18｜本地大模型專業問答：部署方式與多人同時使用
版本：2026-10-31
來源：內部《企業建置手冊》標準技術組合、App 規格、知識庫建置流程（2026-09-27 查核）；官網 /enterprise/（各方案通路）。
來源：Ollama 官方 FAQ https://docs.ollama.com/faq ；vLLM 官方文件 https://docs.vllm.ai/ ；Dify 官方 GitHub https://github.com/langgenius/dify 與 LICENSE（以 Apache 2.0 為基礎加上附加條件：未經授權不可用來經營多租戶服務、不可移除前端 LOGO 與版權資訊）（2026-10-31 查證）。

Ollama、vLLM、Dify 差在哪：
・Ollama：把模型裝在一台電腦上跑的開源工具，安裝簡單；同時處理幾個請求看設定，忙時排隊。適合單機、同時提問人數不多。
・vLLM：開源的模型服務軟體，為多人同時使用設計（PagedAttention、連續批次），提供 OpenAI 相容 API；能把顯示卡效能用得更滿，設定與維護較複雜。
・Dify：開源的 AI 應用平台，本身不跑模型，負責知識庫（附出處）、固定流程、帳號角色與 API，再接 Ollama、vLLM 或雲端模型。授權以 Apache 2.0 為基礎另加條件：公司自用可商用，但未經授權不可拿來經營多租戶服務、不可移除介面 LOGO。
我們的標準組合：「Ollama 跑模型＋Dify 做知識庫與介面」，用 Docker 裝在單台主機；版本固定、寫進部署附件，貴公司 IT 可以審。vLLM 不在目前標準組合。高可用叢集（Kubernetes 等）不在標準範圍。
多人同時用：使用人數不限，速度看「同一時間幾個人在問」。標準驗收會測同時 3 個人提問都能在時限內回完；更多人同時問會排隊、變慢。如果預期幾十人同時問（例如 50 人），評估時依實際用量另估，可能的方向是加顯示卡或改用 vLLM 這類多人服務軟體，以實測結果為準，不預先承諾。

雲端主機（AWS、GCP 等）：可以，主機開在貴公司名下、帳號與付款歸公司。常見是雲端主機＋雲端輔助版（模型用公司自己申請的 API，問題與找到的文件段落會送到模型廠商）；雲端跑本地模型要租 GPU 主機，另行評估。要求資料不出公司設備，選地端版並用內網網頁當介面。

介面：入門方案 LINE 官方帳號或網頁二選一；標準、完整方案 LINE、網頁或內部通訊工具三選一（實際工具評估時確認）。網頁版是公司內網登入式網頁；多通路、寫回 ERP／CRM 另案評估。
跟 ChatGPT 企業版、Copilot 這類雲端服務比：不評論哪家好，差別在資料走到哪裡。雲端服務把問題與資料送到廠商處理，上線快、能力新；地端版在公司設備內處理。先看資料能不能出公司再決定。
