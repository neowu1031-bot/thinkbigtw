AI 的 token 是什麼？為什麼字數上限不是用「字」算

Think BIG 問答圖書館　·　2026 年 11 月 5 日　星期四 ·　English

先說答案

token 是模型處理文字時使用的單位，不等於一個中文字或一個英文單字。同一段文字換模型或換 tokenizer，切分結果可能不同，所以不能用固定字數比例判斷是否超過上限。工作上還要分清楚輸入長度、回答長度與整個上下文的限制。

一、文字先切成模型能處理的片段

依 Hugging Face 的官方文件，常見的子詞切分方式會把文字拆成介於完整單字與字元之間的單位；切法取決於演算法和詞彙表。標點、空白、中文與英文混寫，也要交給實際 tokenizer 處理，不能把畫面上的字數直接當成 token 數。

假設你要整理一份中英混合的作業說明，內含文件代碼、網址與表格。建議用預計部署的 tokenizer 計算整段輸入，而不是先把中文字數乘上一個通用係數。若系統加入角色標記或聊天格式，也要把組裝後的請求納入檢查。這是測量流程的建議，不提供跨模型通用的換算數字。

二、分清楚三個長度

名詞 白話意思 實務上要問
輸入 token 這次送給模型的內容 有沒有包含歷史對話與文件段落
輸出 token 模型這次產生的內容 是否設了回答上限與停止條件
上下文長度 模型處理時可納入的 token 範圍 模型與服務實際設定各是多少

Hugging Face 的生成文件以 max_new_tokens 控制新產生內容的上限；Ollama 的上下文文件則用 token 定義模型可存取的記憶範圍。兩者談的是不同設定，不能把回答上限誤認為整個對話容量。

建議向建置人員確認，問題、系統指示、工具結果、歷史對話與檢索段落，實際有哪些會被組進請求。遇到「明明這次只問一句話卻超長」，先看組裝後的輸入，再決定縮減哪一部分。不要在不知道內容的情況下反覆提高限制。

三、上限要配合工作與設備測試

Ollama 的官方說明指出，提高上下文長度會增加執行模型所需的記憶體。這是該工具的運作說明，不是所有本地系統的容量換算公式。雲端服務與地端工具也可能有不同的輸入、輸出和總長度限制，應以所採配置核對。

本文建議用短問題、長文件、多輪對話各測一次，記錄輸入量、完成狀態、回覆時間與設備狀況。若長文件超出可用範圍，可評估先擷取相關內容、分段處理或採 RAG，但仍要驗收是否漏掉關鍵限制。縮短輸入時，應保留來源、版本與必要上下文；涉及機密資料時，計數工具本身也應符合公司的資料傳送規範。

常見問題

Q1：一個中文字等於一個 token 嗎？
不能這樣換算。應用實際模型對應的 tokenizer 計算。
Q2：輸出上限就是上下文上限嗎？
不是同一個設定；新產生的回答與整個請求可用範圍要分別確認。
Q3：上下文開越大越好嗎？
應依工作測試。Ollama 說明較大上下文需要較多記憶體，不宜只看上限數字。
Q4：機密文件可以貼到線上計數工具嗎？
先確認公司的資料傳送規範；可評估在核准環境使用對應 tokenizer。
