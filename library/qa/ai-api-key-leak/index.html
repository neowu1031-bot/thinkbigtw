AI 的 API 金鑰外洩會怎樣？公司要怎麼保管？

Think BIG 問答圖書館　·　2026 年 10 月 19 日　星期一 ·　English

先說答案

API 金鑰外洩，等於別人可以用你公司的帳號呼叫 AI：依 OpenAI 官方說明，可能造成資料損失、非預期的費用、額度被用光和服務中斷。發現外洩要立刻撤銷舊金鑰、換上新金鑰，再查用量紀錄。平常做到四件事：金鑰不寫在程式碼、不進版本庫、不在聊天裡傳；每個人或每個系統用自己的金鑰；設定到期日並定期輪替；設好花費上限。

一、金鑰通常怎麼外洩

  • 寫在程式碼裡，被推上程式庫。OpenAI 指出，把金鑰提交到原始碼是憑證外洩的常見途徑；公開程式庫等於直接公開，私人程式庫遇到資料外洩也可能流出。
  • 放在瀏覽器或手機 App 裡。OpenAI 明確建議不要把金鑰部署在瀏覽器或行動 App 這類用戶端環境，要經過自己的後端伺服器呼叫。
  • 在聊天軟體、Email、截圖裡傳來傳去。這些紀錄會留在很多地方，很難收回。
  • 寫進 AI 的系統提示。OWASP 提醒，憑證、連線字串這類敏感資料不應該放在系統提示裡，因為系統提示可能被套出來。

二、發現外洩的 4 個步驟

  1. 立刻撤銷。OWASP 秘密管理指南：外洩的金鑰應立即撤銷。
  2. 換新金鑰。產生新的金鑰，更新到使用它的系統；確認新金鑰運作正常。
  3. 查用量。到用量頁面檢查有沒有不是自己團隊產生的使用紀錄。
  4. 清掉外洩的地方。從程式庫歷史、聊天紀錄、日誌裡移除已撤銷的金鑰，並找出外洩原因，避免再發生。

三、平時的 7 條保管規則

依 OpenAI 的〈Best Practices for API Key Safety〉與 OWASP〈Secrets Management Cheat Sheet〉整理：

  1. 一人一把、一個系統一把。OpenAI 不支援共用金鑰；每把金鑰可以個別設定權限。
  2. 設到期日、定期輪替。OpenAI 的專案金鑰可以設到期日，管理者也能限制金鑰的最長效期；新金鑰確認可用後，再撤銷舊的。
  3. 用環境變數或秘密管理服務存放。不要寫在程式碼裡；更高的做法是用專門的金鑰管理服務，讓金鑰與應用程式分開存放。
  4. 提交前自動掃描。OWASP 建議在開發端啟用秘密偵測，在提交前攔下；例如 GitHub 的推送保護（push protection）會在偵測到金鑰時直接擋下推送。
  5. 設花費上限並硬性執行。OpenAI 建議設定每月花費上限並開啟硬性執行，限制金鑰外洩造成的費用；只設提醒不會停止流量。
  6. 限制來源 IP。OpenAI 提供 IP 允許清單，只有指定的 IP 才能用金鑰呼叫，其他請求即使帶著有效金鑰也會被拒絕。
  7. 最小權限與稽核紀錄。每把金鑰只開需要的權限；誰在什麼時候用了哪把金鑰，要留下不能被竄改的紀錄。

另一個常被忽略的重點是：金鑰要申請在公司自己的帳號下。如果金鑰掛在外包商或個人的帳號，費用、用量紀錄和撤銷權都不在公司手上。

常見問題

Q1：OpenAI 的 API 金鑰外洩會怎樣？
依 OpenAI 官方說明，外洩的金鑰讓別人在未經你同意下使用你帳號的額度，可能造成資料損失、非預期費用、額度用光和 API 服務中斷。
Q2：發現 API 金鑰外洩要怎麼辦？
立刻撤銷舊金鑰、產生新金鑰並更新到系統，接著檢查用量紀錄，最後從程式庫歷史、聊天紀錄與日誌中清掉外洩的金鑰並找出原因。
Q3：API 金鑰可以寫在程式碼裡嗎？
不建議。OpenAI 指出把金鑰提交到原始碼是常見的外洩途徑，建議改用環境變數或金鑰管理服務，並且不要放在瀏覽器或手機 App 裡。
Q4：怎麼限制 API 金鑰外洩的損失？
設定每月花費上限並開啟硬性執行、設定金鑰到期日並定期輪替、啟用 IP 允許清單，以及每把金鑰只開需要的權限。
