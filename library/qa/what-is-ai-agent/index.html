AI Agent 是什麼？跟聊天機器人差在哪

Think BIG 問答圖書館　·　2026 年 11 月 3 日　星期二 ·　English

先說答案

AI Agent 是能運用模型判斷下一步、呼叫工具並依結果繼續工作的系統。聊天機器人通常以對話回覆為主，但聊天介面也能接上 Agent，兩者不能只看畫面區分。企業要確認的是它能讀什麼、能做什麼，以及哪一步需要人核准。

一、差別在工作怎麼往下走

Anthropic 的〈Building effective agents〉區分兩種架構：工作流程按照預先寫好的路徑執行；Agent 則由模型動態決定處理程序與工具使用。這是架構上的區分，並非所有服務都採用相同命名。因此，採購或內部提案寫著「Agent」，還不能據此推定它能自行完成整項工作。

方式 假設要整理會議待辦 企業應確認
對話回覆 把你提供的內容整理成清單 資料能否貼入、回答是否正確
固定流程 依預設順序讀檔、整理、存草稿 每一步的輸入與錯誤處理
Agent 依任務選擇工具，查看結果後再決定下一步 工具權限、停止條件與核准點

這個例子只是說明工作方式。是否真的能讀檔、寫入或連接排程，仍取決於實作與授權。不要把自然的對話語氣當成已經完成工作的證據；應查看草稿、工具回傳結果或系統紀錄。

二、能操作工具，就要分清建議與執行

依 OWASP LLM06:2025，功能、權限或自主程度過大，都可能造成過度代理風險。讀取文件的工具若同時附有刪除能力，即使日常只用讀取功能，仍擴大了出錯時的影響。OWASP 建議限制工具功能與權限，並對高影響動作加入人工核准。

企業可先把任務分成「查詢」「產生草稿」「寫入」「對外送出」。例如整理一份待辦草稿，與把內容寫進正式系統，是不同授權。建議從唯讀資料與草稿開始；要增加操作，再逐項確認核准人、可影響範圍及錯誤時的處理方式。這是本文的導入建議，不是所有 Agent 都已內建的功能。

三、先定義一件可檢查的小任務

建議把需求寫成：「讀取指定資料夾內的核准文件，整理本週待辦，列出依據，存成草稿，不自行寄出。」再準備正常輸入、缺少資料、工具失敗與權限不足的情境，確認它能停止並說明原因。驗收對象是整個工作結果，不能只看回答流暢度。

Agent 採用地端模型或雲端模型，是另一項設計選擇。Think BIG 的公開說明提醒，應把部署位置與外部串接分別評估：程式在公司設備上，仍可能透過雲端模型或通訊服務傳送資料。資料能否送出、誰能批准操作，都應在建置前寫清楚。

常見問題

Q1：聊天介面就是聊天機器人嗎？
介面只能說明互動方式。背後是否會呼叫工具與執行工作，要看架構和授權。
Q2：每個工作都需要 Agent 嗎？
不需要。依 Anthropic 的說明，先選能完成需求的簡單做法；固定流程或單次模型呼叫也可能合適。
Q3：Agent 可以在公司設備上跑嗎？
可依系統設計部署；模型、工具、日誌與外部串接要分開確認，不能由安裝位置推定資料流向。
Q4：剛開始應開哪些權限？
建議先開指定資料的唯讀與草稿功能，高影響操作交由人員核准。
