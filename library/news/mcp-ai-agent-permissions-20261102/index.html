MCP · AI Agent · 權限管理

MCP 是什麼？AI Agent 接上公司系統前，先看清楚權限邊界

Think BIG 自媒體部  |  2026 年 11 月 2 日

接上系統之前，先列出 AI 能讀、能改、能送出的內容。連接規格、登入授權與企業核准流程，要分開檢查。

一現象：連接變容易，責任仍留在企業

2025 年 5 月，Anthropic 公布 API 的 MCP connector，說明開發者可以連接遠端 MCP 伺服器，不必另外撰寫連接端程式。[1] 這則公告提供一個具體引子：當 AI 連接外部系統的門檻降低，企業該問的也從「能不能接」走到「接上後能做什麼」。本文引用當年的公告延伸實務，並非新功能快訊。

MCP 是 Model Context Protocol。其工具規格讓伺服器公開可由模型呼叫的功能，例如查詢資料庫、呼叫 API 或執行運算。[3] 但同一套連接方式下，查詢名單與修改名單是不同動作；我們建議，不能因為它們出現在同一個工具選單，就給相同的核准條件。

授權規格另有範圍：本文查閱的 2025-06-18 路徑說明，HTTP 傳輸有對應授權流程，STDIO 則應從環境取得憑證。[2] 工具文件也要求伺服器做存取控制，並建議連接端對敏感操作要求使用者確認。[3] 因此，MCP 的連線成功不能當成公司權限驗收完成。

二各方評價：互通值得採用，授權不能省略

便利的一面：官方連接公告呈現的價值，是減少連接遠端工具時要自行處理的程式工作。[1] 我們的判讀是，統一介面讓團隊較容易盤點工具；但介面一致，不代表各系統的資料範圍與商業責任也一致。

保留的一面：授權文件要求伺服器驗證存取權杖確實是簽發給自己的，不能把任何拿來的權杖都當成有效。[2] 安全文件也提醒，本地 MCP 程式若缺乏限制，可能執行指令、外傳或刪除資料。[4] 這些是實作風險說明，不代表每個 MCP 服務都曾發生事件。

我們主張把討論拆成連接、權限與核准三張表。工程人員確認資料如何流動；系統負責人決定能讀哪些欄位；業務負責人決定哪些變更必須停下來等人。不要讓「已登入」成為所有動作的通行證。

我們建議用一個假設情境檢查權限表：同一位同仁能查詢某份文件，是否也應能要求 AI 把它寄到外部信箱？若答案不同，就要分開列出讀取與送出的條件。核准畫面也應顯示實際文件與收件人，讓人知道這次同意的是哪個動作，而非一次開放後續所有工具。

遇到跨系統工作，我們建議再確認撤權的責任鏈。停用 AI 端工具、關閉 MCP 連接與撤銷下游帳號，是不同的操作點；實際要做哪些，由連接架構決定。驗收時應請維護者示範停止入口，並用測試請求確認結果。若仍有未結束的工作，先留下待處理清單，再決定如何收尾。

我們也建議避免只用管理員帳號展示成功畫面。請負責人指定一個權限較小的測試身分，實際跑允許與不允許的操作，把拒絕原因交給他確認。這樣的證據較能回答交付後的使用範圍，並讓新增權限有明確的比較基準。

◆ 第一手心得

三、我們實際做的時候的心得

以下取自我們審查技能、外掛與 MCP 伺服器的做法，不是產業統計，也不描述特定對象。

1. 先看程式實際做什麼。我們會檢查來源、維護者、授權，以及是否讀環境變數或金鑰、對外連線、執行下載的程式。工具名稱寫「查詢」，仍要看實際呼叫範圍。

2. 權限與版本一起審。我們會確認所需權限並固定版本；審查未通過就不安裝。這不代表第三方程式碼沒有風險，而是每次引入前都有可追溯的判斷。

3. 用清單留下疑問。從上述做法延伸，我們建議把尚未說清楚的連線目的地、寫入行為與憑證來源列成待確認項；不要因為工具可以啟動就直接結案。

四我們的建議：把邊界做成可以重跑的測試

1. 建工具清單。逐項記下系統、帳號、資料夾或資料表、讀寫能力與負責人。查詢工具先用唯讀帳號試行；需要寫入時，另列理由與核准人。

2. 在系統端限制。把資料範圍落在帳號權限、API 授權或伺服器規則，並測試超出範圍的請求會被拒絕。提示詞可以說明規則，但驗收要看真正的拒絕結果。[3]

3. 敏感動作先顯示預覽。我們建議寄信、刪除及修改正式資料先交人確認，畫面列出收件人、目標與變更內容。這是把工具文件的確認建議落成具體流程。[3]

4. 測撤權與留紀錄。用測試資料跑讀取成功、越權失敗與撤權後失敗三種情境，記下時間、操作者與結果。紀錄不放完整金鑰，工具逾時也要能停止。[2][3]

一句話：權限邊界要由系統拒絕與核准證據來證明。

工具清單、核准條件、撤權測試一起交付。

我們主張每個連接都留下用途、資料範圍與維護窗口，並把敏感操作的人工確認列為驗收項。新增工具或擴大權限時，重新審查變動部分。

可延伸閱讀AI Agent 權限設定問答。我們的做法重點是讓負責人看得懂授權，也有能力停止連接。

常見問題

Q1：MCP 是一種 AI 模型嗎？
不是。MCP 的工具規格描述 AI 如何呼叫外部功能，不是模型本身。[3]
Q2：用 MCP 就有權限管理嗎？
仍要在伺服器與連接系統實作存取控制；連線成功不等於授權範圍正確。[2][3]
Q3：本機 MCP 也需要審查嗎？
需要。官方安全文件提醒，本地程式可能有指令執行與資料存取風險。[4]
Q4：哪些動作適合等人核准？
我們建議寄信、刪除與正式資料變更先顯示預覽，由指定人確認；這是實作建議。[3]
